⚠️ The Assumption This Report Breaks

Every single model recommendation you'll find on Reddit, blogs, and YouTube assumes you're running Linux or macOS. The models themselves are trained on Linux-centric tool traces — they will try to call /usr/bin/apt, systemctl, chmod 755, and expect POSIX paths. The community does not account for this. This report does.

  • Models fine-tuned for "tool use" are often fine-tuned on Linux tool use
  • Hermes on Windows runs commands through git-bash (bundled PortableGit), not PowerShell — MSYS path translation applies
  • Blackwell (sm_120) requires torch ≥2.8 — something Ollama handles, but worth knowing
  • Stateful config > CLI args — you hate typing flag strings. This report assumes that.

How Hermes Runs on Your Machine

The shell pipeline

Hermes' terminal tool runs commands through Git Bash (bundled PortableGit at %LOCALAPPDATA%\hermes\git\usr\bin\bash.exe). The installer sets HERMES_GIT_BASH_PATH automatically. This means:

  • You use POSIX shell syntax (ls, &&, |, single-quoted strings) inside Hermes sessions
  • PowerShell builtins (Get-ChildItem, $env:FOO) will NOT work in the terminal tool
  • MSYS-style paths like /c/Users/... work alongside native C:\Users\...
  • But any model that expects a Linux filesystem layout or tries to call Linux-specific binaries will fail silently or produce nonsense

You already know this — you run from PowerShell at the keyboard and Hermes uses git-bash internally. The disconnect matters because trained models don't.
